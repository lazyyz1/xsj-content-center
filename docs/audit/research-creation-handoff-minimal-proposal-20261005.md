# 研究到创作上下文交接最小建议 — 2026-10-05

STATUS：实施前的V0历史建议；已被用户批准的研究体验方案取代。实际实施与验收见 [research-experience-delivery-20261005.md](research-experience-delivery-20261005.md)。当前“带入创作”与“保存/分享”分开，私人选中结论可先带入本人项目，不强制先分享；源研究原样保留。无schema/角色变化。

## 以下保留为实施前建议，不代表当前操作顺序

建议第一小批只做“用户审阅并批准共享的结论 → 当前项目输入框预填引用与创作意图 → 用户明确发送”。复用现有Research分享预览、shareResearchRunToProject、Artifact引用和ProjectAssistant。它比直接搬私人研究全文更容易在已有权限内闭环，但第一小批只覆盖可共享研究结论；纯私人/无可共享来源结果继续留在研究入口。

最小路径：
1. 在现有研究面板保留格式、受众、目标、借鉴项与自有资料选择。目标选已有同workspace项目，不自动创建新项目。
2. 复用buildResearchSharePreview显示服务器实际可共享正文/遗漏与局限；用户批准后调用现有分享API。复用sourceResearchRunId唯一关系，重复点击返回已存在Artifact，不复制私人会话或创作者背景。
3. 进入项目后作为“参考结论”预填ARTIFACT引用，展示成果/项目/版本及原研究run信息，连同researchCreationPrompt已有创作意图。不给targetArtifactId，避免把研究结论本身当改写目标；不自动启动模型、不发送/写入对话、不更换已有草稿。
4. 用户审阅预填内容后发送到原Assistant；后续成果进入W2共享编辑器。离开/替换已有编辑仍经过现有保护，失败保留待发送内容并给出返回原研究的路径。

等价能力核对：/dashboard?start=1 + initialRequest已用于首页新项目首次自动发送，不适合直接挪作本批交接（会自动调用模型）；StudioDefaultMethod已有references/input状态，可扩展为“待发送预填”而非新Task引擎。home-composer/workbench-start已有sessionStorage草稿模式；若跨路由确需过桥，仅存同tab的来源ID、版本和用户创作输入，按user/workspace/project/一次性nonce隔离、消费后清除/超时。不要把私人正文放URL或把浏览器存储当权限凭证。具体过桥实现仍待下一卡选择。

服务端检查点（跳转预填、分享、发送、保存分别执行，不能只靠UI）：
- User/Workspace/Membership有效，目标project同workspace且未归档；客户端传入projectId/来源/版本不能成为授权。
- 私研究run必须本人requestedBy/session.createdBy、COMPLETED、savedAt非空；只允许服务器分享预览输出进入团队Artifact，拒绝拿他人的private run与跨workspace来源。
- 分享事务提交时再次确认有效成员、空间与写角色；VIEWER不能通过交接写共享结论/候选。已有代码需在下一批定向核对提交时disabledAt条件，不能把先前一次校验冒充完整竞态验收。
- 默认Assistant线程仍按创建者隔离；目标项目若已有其他成员默认线程，本次收尾已明确拒绝使用。不能为交接共享他人的对话或接管线程；若要每成员独立持久对话，必须先单独批准数据/索引方案。
- 引用Artifact必须获准读取、来源同workspace/目标project、branch未删除；预填时展示/记录版本，发送时若已变化应重新审阅，不默默把更新版当批准版。
- 使用RESEARCH完整私人引用与最终保存团队Artifact是两个披露边界。若下一批选择私人全文直达创作，应先确定服务端认可的披露确认/快照协议，不能只加提示并用现有Artifact POST把私人内容自动共享。
- 交接本身不调用模型/采集/邮件；显式发送后的计费与Provider范围沿用已有授权。新成果保存继续existing expectedVersion/写角色/来源Message actor scope；失败/重试不得重复分享或覆盖旧稿。

下批最小验收建议：既有项目不新增；同tab草稿/资料/借鉴意图连续；取消共享保持私人；仅批准预览内容进入项目；回退/重复点击/来源版本变化；他人private run/跨workspace/disabled成员/VIEWER写入/他人线程拒绝；无隐式模型调用。无shareable blocks（尤其纯主题USER_INPUT结果）明确停留私人入口，不伪造“交接成功”。

决定点：是否先实施以上“已批准共享结论”的小闭环。私人完整研究到私有创作、多人各自Conversation及历史版本固定引用另卡；本建议不预先授权这些变化。


## 最终验收后的具体交互建议（仍未实施）

现有研究入口会链接到已保存结果分享区，文字包括“审阅并加入项目 →”“加入项目 / 交给 Agent →”“带入项目与 Agent →”。分享区已经有“加入项目”和“加入项目并开始创作 →”。建议只扩展后者：先批准共享，再进入已有项目，以待发送内容预填当前 Agent。保留“生成我的版本”的私人研究创作路径；该按钮现有行为会调用模型，不能把它说成纯预填。

共享前显示服务器实际分享预览的完整正文、结论/来源数、遗漏和私人背景排除情况、来源与局限。明确显示目标工作空间及项目，并提示“该工作空间有读取权限的有效成员（含 VIEWER）可见”。现有 Artifact 并非仅项目创建者可见，也没有独立项目成员 ACL；选项目不建立客户隔离。纯 USER_INPUT 主题等没有可分享结论的结果继续留在私人研究。

预览目前只读，没有逐块筛选或任意改写后共享的 API。可以换项目、取消审阅勾选或离开；确认共享前不写共享成果。可在预填阶段调整受众、目标、格式、借鉴项，发送前移除引用。编辑共享正文或逐块选择须另定 API 范围。共享成功后取消创作预填不删除已共享成果或撤回可见性，界面应说明。

预填使用获批共享快照的 ARTIFACT 引用，显示项目、来源和版本；不搬私人研究全文/会话，不设置 targetArtifactId，不默认改写研究结论。不能复用自动发送的 initialRequest / start=1。明确发送前不调用模型、采集或邮件，也不自动保存 Assistant 消息/成果。目标线程属于其他成员时继续拒绝，可换允许的项目或只共享，不接管对话。

持久写入分阶段说明：明确共享沿用 Artifact、DraftBranch、DraftRevision、AuditLog 写入及分享幂等关系；明确发送沿用 AssistantMessage/AIRun/审计；明确保存沿用成果/版本写入。预填不新增数据库实体，不自动增加以上写入。跨路由若复用同 tab sessionStorage 草稿过桥，会新增一次临时浏览器草稿写入：只存来源 ID/版本和用户意图，按用户/空间/项目/nonce 隔离，消费或过期清除。具体方案仍待讨论；本轮未实现过桥或强退恢复。

旧输入不能默默覆盖。ProjectAssistant 输入与 Artifact 正文是不同状态，Artifact 保护不代表 Assistant 输入已被保护。下一小批应保留旧输入，提供追加、确认替换或取消；资料、借鉴和引用选择不悄悄改变。Artifact 脏稿继续保存/放弃/取消。发送前重验来源版本与服务端 scope，变化时重新审阅，失败保留待发送内容。

不新增角色、扩大权限或共享私人对话。下一卡需补验分享事务 disabledAt 竞态及有效用户/空间/成员、写角色、研究本人归属/保存状态、目标项目、引用权限/版本、线程归属、重复点击。以上是建议和待验收合同，不是本轮已落地功能。
