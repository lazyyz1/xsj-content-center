# AI 内容工作台 Web 视觉整合 V1 产品任务基线

日期：2026-10-08，Asia/Singapore。来源：本轮产品负责人明确指令及补充要求。

本任务对 `xsj-content-center` 现有 Web 前端进行原创视觉改造和页面重排，保护现有业务、身份、数据和服务边界。当前只执行检查点 1 的架构审计与页面映射；后续每个阶段以明确任务单施工并分别验收。本文件保留任务要求，不改写 PRODUCT.md、ARCHITECTURE.md、LEGACY.md 或 AGENTS.md。

## 项目目标与参考边界

以沉浸式宇宙首页与 Apple 风格专业内页建立统一、可演示、可逐步接入真实业务的前端系统。参考 [Mineradio-paused](https://github.com/XxHuberrr/Mineradio-paused) 的空间层次、悬浮控件、深色舞台和镜头交互思想。所有 UI、布局细节及视觉资源原创实现，不移植参考项目源码、品牌、Logo、贴图或受保护的原创视觉表达。

重点是验证统一产品形态，不同时进行大规模后端重构，不合并第二套项目的数据库或身份体系。最新完成度以本地实读源码、依赖、运行与当次测试结果为准，历史审阅和 GitHub 默认页面不能代替核验。

## 已锁定的设计决策

1. 沉浸式宇宙首页与 Apple 风格专业内页，Web 桌面端优先。
2. 原创烟熏光学玻璃星球，配合精细星轨、低密度粒子、空间纵深和受控镜头交互。
3. 首页保留空间结构、悬浮面板、底部控制台的设计思想；不改成传统 SaaS 后台，不用普通背景图堆叠代替空间材质。
4. 底部 Dock 固定为：首页、研究、创作、内容、复盘。老板驾驶舱为顶部独立入口。
5. 左侧资源栏管理 IP、项目、最近任务并支持折叠。首页首次默认收起，工作页首次默认展开，之后尊重用户偏好。
6. 右侧 AI 面板按当前任务显示。避免同一任务同时出现两套长期驻留的 AI 对话区。
7. Visual Lab 实时调节玻璃材质、轨道、光照、粒子、动画和界面视觉。
8. 普通用户只有简易外观设置，高级视觉设置只给服务端核验过的管理或演示人员。
9. 支持个人预设和公司默认预设。第一阶段先实现本地保存、恢复、导入导出；公司级发布后续接入服务端。本机公司预设草案不称为已发布公司默认。
10. AI 创作默认采用 AI 对话与稿件编辑双核心工作区，支持可调双栏、专注编辑与按需资料辅助。
11. 不调用 finesse。新视觉从上述需求重新设计，之前生成的视觉不作为新设计基础；业务接口、状态管理、权限和保存逻辑按审计结果复用。

## 页面信息架构

全站统一使用顶部操作区、可折叠资源侧栏、底部 Dock 和独立工作区；复杂业务保留原有深链与上下文。

| 页面 | 目标职责 |
| --- | --- |
| 首页 | 动态玻璃星球、最近项目、今日任务、核心功能入口；找到工作与继续工作。 |
| 研究中心 | 行业日报、对标账号、单条拆解、趋势选题、来源核对、研究结论审核及显式采用。 |
| AI 创作 | AI 对话、可调双栏、Skill、知识引用、稿件编辑、版本和真实保存状态。项目创作与私人独立稿件均保留。 |
| 内容资产库 | 网格/列表、稿件版本、关联 IP、待拍、已拍、发布管理。现有私人稿件和项目成果权限不混合。 |
| 数据复盘 | 视频关联、截图/手填数据、人工确认、指标快照、AI 优化建议。平台审核不是表现数据复盘。 |
| 老板驾驶舱 | 团队经营数据、IP 表现、内容趋势、成员进度和下钻；双模式明确区分演示视图与真实业务视图，正式口径另行验证。 |
| 知识与管理 | 保留资料、Skill、设置、成员、系统与平台管理的已有入口，统一视觉体系。 |

## 技术与业务边界

- 优先保留 Next.js、React、TypeScript。引入 Three.js、React Three Fiber、GSAP 前先检查现有依赖与本地候选分支。
- 分离 3D 场景、通用 Shell、业务组件、数据适配和演示 fixtures。按复用、扩展、适配、简化、最后新增的顺序判断组件。
- 不删除、覆盖或重写已经可用的创作、研究、保存、登录等业务功能；不擅自修改业务模型、Schema、迁移、身份系统或数据库。
- 正式施工必须在独立分支，并保存能恢复完整本地工作状态的基线。仅有提交号不能代表尚未提交的最新源码。
- 不在真实 API 失败时静默切换演示数据。真实、演示、未开发、空数据、加载、失败须分别展示。
- 未开发操作明确不可用或说明状态，不模拟真实保存成功，不自动发送 AI 请求。
- 3D 支持关闭、暂停、降质、后台暂停、WebGL 不可用或上下文丢失时的原创替代展示。
- 支持减少动态效果、键盘导航、焦点反馈、抽屉关闭与焦点归还，以及长文本阅读和编辑。
- 正式权限由服务端核验。隐藏按钮、前端角色标记、URL 参数和 localStorage 不能授予高级视觉、公司发布或经营数据权限。
- 切换页面、稿件、项目或退出专注模式时，保留未保存内容的保护逻辑与版本冲突处理。

## 施工前审计交付

1. 当前页面与路由清单，区分独立页面、兼容重定向、设置拦截页和 API。
2. 各模块的代码接线、权限、真实 API 基础、测试和运行验证状态；不凭端点数量给出虚假的完成百分比。
3. 新旧页面映射表及需保留的深链。
4. 可复用、需重做的组件及依赖评估。
5. 可能破坏现有业务的风险、规避方案与回退方式。
6. 建议的组件结构、分阶段实施顺序，以及直接接外壳与隔离展示入口的取舍。
7. 本地与 GitHub 的基线差异、未提交工作及源码指纹；不将旧默认分支误当最新整合状态。

先将风险与方案交给负责人评审，再明确下一个开发任务。本轮不自主贯穿所有开发阶段。

## 开发阶段与检查点

| 开发阶段 | 范围 | 退出条件 |
| --- | --- | --- |
| 施工前审计（本轮） | 实读本地代码、路由映射、风险、组件与依赖评估、浏览器现状和基线检查。 | 检查点 1 报告可供评审。 |
| 第一开发阶段 | 新布局、原创沉浸首页、可折叠侧栏、固定 Dock、Visual Lab。 | 检查点 2：浏览器实际查看材质、空间动画、导航；提供截图、测试和未完成项。 |
| 第二开发阶段 | AI 创作双栏、专注模式、老板驾驶舱演示版。 | 检查点 3：实际打开创作工作台及双模式老板看板。 |
| 第三开发阶段 | 研究、内容资产、数据复盘的视觉与主要交互统一。 | 页面及流程逐项验收，现有入口继续可达。 |
| 第四开发阶段 | 逐个接入已验证可用的接口，测试与回归。 | 检查点 4：首页到创作再到驾驶舱连续操作，演示/真实/未开发状态明确。 |

检查点交付与产品负责人通过验收是两个状态；审计交付不表示玻璃首页、业务页面或联合演示已完成。

## 验收要求

- 1920px 和 1440px 桌面布局正常，长文本可读，编辑器有足够空间。
- 首页达到统一的深空材质质感，保留空间层次、烟熏玻璃、镜头反馈及动态交互。
- 侧栏、Dock、抽屉、页面切换、Visual Lab 正常；视觉参数可即时预览、保存、恢复、导入导出。
- 真实数据、演示数据、未开发状态清楚，未授权访问、未保存丢失、假成功均不出现。
- 创作、研究、保存、登录等已有功能不回归；包含 API 失败、版本冲突、跨用户/跨工作区和刷新恢复场景。
- 交付实际可运行的 Web 地址、页面截图、代码 diff、当次测试结果和未完成项。
- 浏览器必须实际操作评审；编译通过和静态截图不能替代动态验收。
