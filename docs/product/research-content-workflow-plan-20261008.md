## 为什么几轮效果仍不对

1. 之前把重新设计等同于导航、卡片、标题和CSS调整，工作对象没有改变。/research/benchmarks 与 /research/works 仍是两套作品列表，阅读状态和收藏操作被分在不同页面。
2. 采用研究仍走“选择旧项目—填写意图—勾审阅—临时交接—返回dashboard—再次确认”的旧流程。它不会创建独立创作会话，sessionStorage交接30分钟后过期。项目Assistant默认只使用最早的主thread，多条内容容易继续在同一对话里做。
3. 报告页虽有段落对应，但原视频藏在操作折叠中，账号信息、面包屑、标签、报告操作重复占用首屏。工作主线与工具设置没有稳定分工。
4. 收拢入口时遗漏了可用能力：账号方法归纳服务与组件还在，却没有当前账号页入口；跨账号/focus也没有明确入口。
5. 新增绿色局部设计体系，覆盖原全站灰白紫token。它使研究区偏离项目已有整体风格，并未解决功能关系。

不改 PRODUCT/ARCHITECTURE/LEGACY/AGENTS 来为旧实现背书。项目仍是长期容器，一条内容是其中独立工作的对象。数据方案先查可复用的DraftBranch、Artifact、AssistantThread、ContentIdea等能力，再确定适配或最小新增，避免再造平行抽象。

## 页面分工

| 工作区 | 主任务与默认内容 | 进入下一步的方式 |
| --- | --- | --- |
| 研究—日报 | 直接读外部新闻：日期、来源、标题、摘要与原文。资讯/早报是阅读视图，无介绍首页。收藏和稍后读是个人筛选。 | 可选一条作为研究来源或创作参考；无需先配置知识/定位。 |
| 研究—老师与对标 | 上方账号，下方同一份作品列表。点账号就过滤下面作品，支持多选账号比较。老师/对标只是可选学习意图。 | 从作品打开拆解；账号深入观察与可学方法是二级视图。 |
| 单条作品—内容拆解 | 原内容、主线、实际段落推进和对应解读共同可见。原文按需展开；原视频不藏在“报告操作”里。真实时间码才联动播放。 | 选段落、方法或结论，明确“用来创作”，进入自己的内容任务。 |
| 研究—保存与回看 | 一份档案，按资讯/作品/研究结论及收藏/已读/历史筛选；旧研究标记兼容来源。 | 继续追问或再次采用；不增加重复收藏入口。 |
| 独立内容—创作 | 已采用的参考结构放旁边，主要区域写自己的角度、骨架或稿件；自己的真实证据与参考区别显示。可先写也可先说，语音转录后可编辑。 | 独立会话、稿件与版本始终属于同一条内容；可跳过研究直接写日常。 |
| 独立内容—制作与记录 | 同一条内容内查看版本、交接稿件、待拍/已拍、关联成片、手动发布状态、数据和单条复盘。 | 日历和跨内容总览读取同一记录，不重新生成另一条任务。 |
| 页面助手 | 默认收起，围绕当前主动选择的资讯/账号/作品进行追问，成果页面继续可见。 | 研究和创作各自保存会话；只有明确采用的内容跨过去。 |

趋势观察、素材研究、自定义研究、账号深度分析和跨账号归纳要有清楚入口；放入相关工作区的深入动作，不删掉它们。

## 明确撤掉的必经步骤

- 研究介绍首页、两个互不一致的作品列表和重复的收藏入口。
- 必须先选学习目的才能阅读的产品暗示。
- 创作前强制填写完整定位、公司知识或一长串表单。
- 用两次审阅和临时草稿模拟独立创作。
- 自动把整份报告、私人研究聊天和公司资料塞入创作。
- 每条内容默认必须经过模型评估/审核，才能保存稿件或手动交接。

权限检查仍在服务端；共享或发布仍是明确操作。移除多余的交互门槛，不移除数据范围与权限。

## 拆解的内容规则

复用现有证据与报告contract。源码已支持动态structureBlocks、逐字引用和观察/假设区分，不重复重造分析引擎。

- 结构从这条内容中识别：可由故事、演示、论证、问题解答等组成，不套统一钩子—背景—案例。
- 表达观察附引用；观众反应/效果解释显示为假设及限制。
- 点赞相对倍数只辅助挑选作品，不是爆款原因证明。
- 没有原文、画面或时间码时明确缺口，不补造。
- 模型真实质量与已保存报告的可读性必须实测，不能用prompt和模拟报告通过代替。

## 分批执行与分工

### 0. 产品与界面：先确定行为和视觉基线

输出四个可交互预览：日报、账号/作品、作品拆解、独立创作。全部继承原灰白紫风格。每个预览要显示真实内容、无报告、同步失败和手机窄屏；走完从阅读到采用再回来继续的操作，不能只给静态截图。

明确保留能力矩阵，逐项检查入口，恢复账号方法归纳与跨账号比较。

### 1. 内容/对话服务：先让“独立”成为数据事实

一条内容拥有明确会话、引用快照、稿件/版本和状态；研究采用持久保存，不依赖当前标签页的30分钟草稿。研究端一次明确操作即可创建/打开内容任务；直接日常创作使用同一能力。

验收：任务A/B不串话；刷新和重开不丢参考与草稿；来源版本可追溯；不同用户/项目不能读取彼此私有对话；未采用资料不自动进入创作。

### 2. 研究前端：重建内容浏览和阅读工作区

合并两份作品列表；账号选择立即影响作品；未读、收藏、忽略和排序在同一列表完成。整理日报与档案，不增加新介绍层。报告主区把原内容和动态分析对齐，恢复深入研究入口。

验收：真实已保存数据直接可见；筛选与返回位置保留；没有报告不显示假分析；手机无页面横向溢出；旧链接仍可访问。

### 3. 创作前端与助手：接上真实独立内容

采用结构后直接进入内容工作区；参考在旁，自己的表达与稿件在主区。骨架/逐字稿为可选输出，不强制一种脚本。公司知识、资料和Skill按需选用。

研究助手支持围绕当前选中对象追问，保留会话，不把“提交后关面板跳另一页”当作页面助手。创作助手只服务当前内容任务。

验收：一键采用不自动发消息、不自动生成或共享成果；完全不研究也能直接写；已采用参考与自己的稿件始终分开。

### 4. 后续内容工作流：手动持续做完（不属于本批交付）

在同一条内容中接上稿件版本、交接、待拍/已拍、关联成片与手动状态。复用现有日历和发布包的有效部分；不能让旧MotherContent/APPROVED/QualityGate依赖变成日常写作必经门槛。

自有视频表现数据与单条/跨视频复盘需要专用设计。对标观察不等于自有数据，现有ReviewRecord是稿件审核，不等于表现复盘。

自动剪辑、自动发布和平台联动日历后续单独评估。

## 后续已确认的页面选择

已确认稿件编辑器为主、参考结构在旁、助手按需使用；先写再归类，归类后仍私有，模型建议须明确采用。首批是研究到独立创作，制作与表现复盘留到后续。

## 验收与工期

验收以一条内容的完整行为为准：读新闻/作品 → 核对原内容 → 拆解 → 选择采用 → 独立写作 → 修改版本 → 离开后回来继续。另验证直接日常写作与任务A/B隔离。

现阶段不给天数承诺；先确认四个核心页面、内容/会话契约和首版生命周期范围，再按明确交付单元估工期。旧20–24天估算作废待重算。
