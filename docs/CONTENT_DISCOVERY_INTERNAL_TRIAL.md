# Content Discovery 内部试用说明

## 试用目标

验证真实创作者能否在没有工程人员解释的情况下，完成“发现方向 → 查看依据 → 保存选题 → 补充研究 → 开始创作”的完整流程。试用重点是观察理解成本和实际卡点，不是验证未来功能设想。

## 试用对象

- 日常负责选题、研究或内容创作的内部成员
- 尽量包含第一次使用本产品的人
- 观察员只记录行为和原话，不提前解释正确操作

## 三个核心概念

- 素材：我保存下来的参考内容。
- 选题：我正在考虑要做的内容方向。
- 内容项目：我已经正式开始创作的内容。

## 建议试用流程

1. 从“内容发现”进入，不做功能讲解。
2. 让用户依次完成下方 6 个任务。
3. 每个任务单独计时并记录是否需要帮助。
4. 遇到停顿时先询问“你现在在找什么”，不要直接指路。
5. 试用结束后填写反馈模板，并按 P0–P3 汇总问题。

## 测试任务

### TASK 1

搜索一个自己平时关注的内容方向。

### TASK 2

找到一条值得参考的内容并加入选题。

### TASK 3

添加一个真实对标账号并查看最近作品。

### TASK 4

查看趋势机会，找到一个值得研究的方向。

### TASK 5

查看“今天值得做”，打开其中一条的推荐依据。

### TASK 6

从推荐或选题一路进入内容项目 Studio。

## 每个任务的观察记录

- 是否成功：YES / NO
- 耗时：
- 是否需要帮助：YES / NO
- 卡点：
- 用户原话：
- 是否产生误解：

重点观察用户在哪里犹豫、不知道下一步、觉得信息过多、频繁返回，以及是否混淆素材、选题和内容项目。特别记录用户是否理解“今天值得做”的推荐依据。

## 反馈与问题分级

反馈使用 [CONTENT_DISCOVERY_TRIAL_FEEDBACK.md](./CONTENT_DISCOVERY_TRIAL_FEEDBACK.md)。保留用户原话，不要提前替用户总结。

- P0：无法完成主链、数据错误、权限错误或误收费。
- P1：关键流程难以理解或受到明显阻塞。
- P2：视觉、文案或效率问题。
- P3：未来功能建议。

用户提出自动化、长期偏好、预测或其他新能力时，只记录为 P3，不在本轮试用中开发。

## 外部服务说明

打开内容发现、推荐详情或已有趋势不会自动调用外部服务。只有用户明确点击搜索、加载趋势、加载对标作品或生成 AI 推荐时，才会发起对应请求并可能产生费用。
